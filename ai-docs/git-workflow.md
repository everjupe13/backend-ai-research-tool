# Работа с Git в проекте

Документ описывает соглашения по работе с git, принятые в проекте.
Будет расширяться по мере появления новых паттернов.

---

## Снятие файлов со staging

В проекте используется:

```bash
git restore --staged .
git status --short
```

Применяется, когда:

- Случайно застейджили лишние файлы и нужно вернуть их в working directory
- Решили разбить один большой коммит на несколько — снимаем всё со staging, добавляем по частям
- Перед коммитом хочется пересобрать список файлов с нуля

Содержимое файлов в working directory при этом не меняется — `restore --staged` трогает только индекс. `git status --short` сразу показывает компактный вывод (`M` — изменён, `D` — удалён, `??` — untracked).

## Иерархия `git reset` — чтобы не путаться

| Команда | Что меняет |
|---|---|
| `git reset` / `git reset HEAD` | Только staging, файлы целы |
| `git reset --soft HEAD~1` | Откатывает коммит, изменения остаются в staging |
| `git reset --mixed HEAD~1` (default) | Откатывает коммит, изменения в working dir |
| `git reset --hard HEAD~1` | **Уничтожает изменения в working dir и в staging** |

Опасен только `--hard`. В проекте `--hard` никогда не запускается без явного подтверждения.

## Соглашения по коммитам

Используется conventional commits format. Подробности — в `.claude/skills/commit/SKILL.md`.

### Префиксы

| Префикс | Когда использовать |
|---|---|
| `feat` | Новая фича или эндпоинт |
| `fix` | Багфикс |
| `refactor` | Изменение кода без изменения поведения |
| `chore` | Зависимости, конфиги, тулинг |
| `docs` | README, CLAUDE.md, комментарии |
| `test` | Добавление или фикс тестов |
| `migration` | Новая TypeORM миграция |

### Формат сообщения

```
<prefix>: <короткое описание на английском, максимум 72 символа>

<необязательное тело — только если "почему" не очевидно из заголовка>

Co-Authored-By: Claude <MODEL_NAME> <noreply@anthropic.com>
```

- Заголовок — повелительное наклонение (`add`, а не `added`)
- Без точки в конце
- `<MODEL_NAME>` подставляется моделью, создающей коммит (`Opus 4.7`, `Sonnet 4.6`, `Haiku 4.5`)

## Что НЕ делаем

- **Не используем** `git add -A` или `git add .` вслепую — всегда добавляем явный список файлов
- **Не коммитим** `.env` и любые файлы с секретами (ключи, токены, креды)
- **Не используем** `--no-verify` для пропуска хуков — если хук падает, чиним проблему
- **Не делаем** `--amend` опубликованных коммитов — только новый коммит сверху
- **Не делаем** `git push --force` в `main` ни при каких условиях
- **Не делаем** `git reset --hard` без явного подтверждения пользователя

## Полезные алиасы (опционально)

Если хочется добавить shortcuts в `~/.gitconfig`:

```ini
[alias]
  st = status --short
  unstage = restore --staged
  last = log -1 HEAD --stat
```

Тогда `git unstage .` = `git restore --staged .`.
